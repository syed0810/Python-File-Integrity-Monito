File Integrity
Monitor

A lightweight security tool that detects whether files in a monitored folder have been modified, added, or deleted by comparing their SHA-256 fingerprints against a trusted baseline.

Python
SHA-256
JSON
Recursive scanning
“If the file changes, its fingerprint changes. The monitor catches the difference.”
01 · The problem

What are we trying to detect?

A filename alone cannot tell us whether a file is still trustworthy. A file can be changed while keeping the same name.

01

Modified

An existing file's contents change, producing a different SHA-256 hash.

02

Added

A new file appears that was not present when the trusted baseline was created.

03

Deleted

A file that existed in the trusted baseline is no longer present.

02 · Core concept

SHA-256 = a digital fingerprint

SHA-256 is a cryptographic hash function, not encryption. It produces a fixed-size fingerprint from file contents. Even a tiny content change normally produces a completely different hash.

Example

file1.txt
Hello

SHA-256 → 185f8db3...81969

Hello!

SHA-256 → new completely different hash

Why it matters

The monitor does not need to store a second copy of every file. It stores the fingerprint and checks whether the fingerprint changes later.

The baseline is the trusted snapshot of the monitored folder at a known-good point in time.

04 · Detection

Compare old vs. current state

MODIFIED

File exists in both scans, but:

old_hash ≠ new_hash

ADDED

File exists in the current scan but was not in the baseline.

DELETED

File existed in the baseline but is missing from the current scan.

Baseline created
Trusted file paths + SHA-256 hashes are stored.
Folder changes
A file is modified, a new file is added, and another is deleted.
Rescan
Current hashes and paths are compared with the baseline.

06 · Implementation

Built with simple Python components

hashlib

Provides SHA-256 for generating file fingerprints.

os.walk()

Recursively scans the monitored directory and subfolders.

json

Stores and loads the trusted baseline in a human-readable format.

Memory-friendly hashing

Files are read in 4096-byte chunks rather than loading an entire large file into memory.

Simple user flow

1. Set Baseline → 2. Scan for Changes → 3. Review the report.

07 · Limitations

What would I improve?

Current limitation

The baseline JSON is not independently protected. An attacker with permission to modify it could potentially replace the trusted hashes.

Future improvements

Protect the baseline with access controls or a cryptographic signature, add continuous monitoring, and generate alerts/logs for detected changes.

The core principle stays the same: establish a trusted state, fingerprint it, then detect deviations.
